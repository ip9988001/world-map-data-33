# 自研模式（SELF-DRIVE）母体规格

> 本目录是**母体**，不是某个项目的施工补丁。
> 母体只由「不变量 + 契约 + 骨架 + 适配器」构成，**不含任何具体任务的代码**。
> 任何新任务，只允许往 `05-适配器` 这个插槽里插，其余部分一行不改。

---

## 一、这个母体要解决什么

自动化作业反复死在同一批地方，根因从来不是「能力不够」，而是四件事：

1. **判定权错位** —— 让脚本判「合格/不合格」。
2. **证据缺失** —— 结论先出，证据后补，事后无法复算。
3. **失败不分型** —— 一律重试，把 logic 错误重试三次，三次白跑。
4. **无人报警失效** —— 进程还在但已经不产出，监工说「健康」。

母体把这四件事在结构上堵死，**不依赖执行者的自觉**。

---

## 二、三层结构（可复制性的唯一解法）

| 层 | 名称 | 内容 | 是否允许为新任务修改 |
|---|---|---|---|
| **L0** | 不变量 | 十条铁律（`00-不变量.md`） | ❌ 永久冻结 |
| **L1** | 骨架 | 目录约定 / 信箱 / 账本 / 报告 / 自检 / lint（`04-骨架与适配器.md`） | ⚠️ 只在「规格有洞」时改，且必须记进 `06-复盘` |
| **L2** | 适配器 | 怎么取数、怎么判「这一层成了」、怎么分片、产物怎么打包 | ✅ **新任务唯一允许写新代码的地方** |

**执行纪律一句话：新任务只写 L2。谁想改 L0/L1，先证明是规格有洞，不许打补丁。**

「万能」不等于能预测所有任务。万能 = 所有任务都只往一个插槽里插。

---

## 三、人在这套里的唯一位置

**人不出现在循环里。** 人的全部职责是点火时写一份静态策略（目标 / 不可接受的结果 / 预算 / 可跳过的边界），然后退出。

判定的准确性来自**知识**，不来自「有人在场」。把不具备相应知识的人放进回路，只会产生两种损失：否决正确结论、批准错误结论。

判定权唯一归大脑。为了防止大脑「自证」，不靠人来复核，靠：

- **可复算证据** —— 任何第三方（人或另一个 AI）只凭证据指针就能重算出同一结论（`03-可靠性与验收.md`）
- **阈值运行期只读** —— 运行中禁止修改自己的验收标准，要改必须开新一轮并留 diff

## 五、怎么证明母体成立

**不由作者评价，由「空仓再造」证明**：拿一个全新空仓库，只给本目录，不给任何历史代码，看能否在限定时间内起一条跑通的流水线。

跑通 = 母体成立；跑不通 = 规格缺东西，缺什么补什么。

详细协议见 `03-可靠性与验收.md` 第五节。

---

## 六、健康度自查（三步）

1. 连续若干轮都在改 L0/L1 → **报警**，说明规格有洞，回 `01-搭建SOP.md` 的 D1 查，不是继续打补丁。
2. 有结论但找不到证据指针 → 该结论作废，不算数。
3. 有「跳过」但没有状态机归档 → 债务消失，必须补 `blocked` 条目。
