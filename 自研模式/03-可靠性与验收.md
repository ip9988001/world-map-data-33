# 可靠性机制与母体验收

> 可靠性不靠自觉，靠四道机器闸 + 一份可执行的验收协议。

---

## 一、四道机器闸

### 闸 1：禁忌 lint（`lint_pipeline.py`）

把 `00-不变量.md` 的十禁变成可执行扫描，对仓库直接出报告：

| 规则 | 扫描方式 | 告警级别 |
|---|---|---|
| 禁 `|| true` 静默吞错 | 扫脚本中的 `|| true`、`2>/dev/null` 裸吞 | P0 |
| 禁脚本判合格 | 扫脚本中对 `合格/不合格/pass/fail` 的赋值 | P0 |
| 禁工头推人看的通道 | 扫工头文件里的 webhook / 推送调用 | P0 |
| 禁单一数字判空壳 | 扫 `< 2KB` 之类的单判据 | P1 |
| 禁 push 不重试 | 扫 push 处是否缺 fetch+rebase+retry | P0 |
| 禁覆盖写账本 | 扫对账本的 `w` / `truncate` / `overwrite` 模式 | P0 |
| 禁阈值运行期写 | 扫对 policy / 阈值文件的写操作 | P0 |
| 禁跳过不留证据 | 扫 blocked 条目是否缺五字段 | P1 |
| 禁判定权下放 | 扫工头是否出现「结论/verified/approved」字段 | P0 |
| 禁改验收环节规则 | 对已 `verified` 的 STEP 做 diff 检测 | P0 |

**放行条件**：P0 必须为 0。P1 允许存在，但必须在 blocked 里登记理由。

### 闸 2：selftest 四断言（每次上线前）

1. 信箱：投一条 → claim 到 → done，状态机正确
2. 并发：processing 非空时第二次 claim 必须返回 BUSY
3. 退信：信封缺字段必须被拒收且回写原因
4. 折叠：一段时间内的多条 P2 必须合并为一条

### 闸 3：复算脚本（`verify_from_evidence.py`）

只读证据（artifact / 文件 / 查询），重算结论，与账本逐行比对。

- 不一致 → 该轮作废
- 证据缺失 → 该结论作废
- **判据：换一个人或另一个 AI 跑，必须得到同一结论**

这是「无人参与」能成立的唯一根基。没有它，判定权归大脑就等于自证。

### 闸 4：退化检测

- 连续 N 轮修改 L0/L1 → **报警**：规格有洞，回 D1 查，不许继续打补丁
- 连续 N 条结论无 `script_sha` → 报警：口径混用风险
- 报警频率异常（假红过多）→ 说明容忍窗或 ETA 拍错，先修 ETA

> 前两道闸管工人与工头，后两道闸管大脑。缺了后两道，母体只是「管得住手脚、管不住脑袋」。

## 二、假象识别清单（这些「看起来成功」的都是假绿）

| 假象 | 真相 | 正确判据 |
|---|---|---|
| workflow 全绿 | 可能空跑 0 行也绿 | 看 manifest `actual` 与 declared 的差 |
| 进程还在 | 可能已不产出 | 心跳产出（mtime / 完成计数）在动 |
| 文件存在 | 可能只有几百字节的错误页 | 多判据（行数 + 结构 + hash），单一数字不算 |
| 日志无报错 | 可能静默跳过 | 账本里每单元都有终态 |
| 跑完了 | 可能只有单副本、随 runner 消失 | Release 可下载 |
| 数字对上了 | 可能口径不同（新脚本 vs 旧脚本） | 带 `script_sha` 比 |

## 三、时间与外部依赖的硬事实

- 平台级定时任务**不可靠**（声明 15 分钟、实测间隔 2~6 小时、均值近 4 小时）。监督者不许挂在它上面；要么放可控定时器，要么链式自触发。
- 单 job 有硬时限（常见 6h）。超过 5h 的作业必须分片。
- 外部服务会消失。上游缺失是常态，不是异常 —— 所以 `upstream` 是一等分类，不是错误。

---

## 四、成本纪律

- 一次性小活不值得搭架子（搭架约 1~2 小时）。三问不过就别硬套。
- 机器可验优先，大脑可验次之，人可验最后。每往上一层，单次成本高一个量级。
- 不要把「检查」写成「再跑一遍全量」，检查必须比全量便宜一个量级。

## 五、空仓再造验收协议（母体自身的验收）

母体的质量**不由作者评价**。用下面的方法证明：

### 步骤

1. 开一个**全新空仓库**（干净账号、干净环境最佳）
2. 只给它本目录（`自研模式/`），不给任何历史代码、不给口头提示
3. 指定一个**中等的真实任务**（有真实上游、有真实失败、非玩具）
4. 由执行方独立完成 D0~D6
5. 记录：耗时 / 卡点 / 需要追问作者的问题 / 触碰 L0-L1 的次数

### 判据

| 结果 | 结论 |
|---|---|
| 独立跑通，零追问，L0/L1 未改 | **母体成立** |
| 跑通但需追问 ≤3 次，改动仅在 L2 | 母体基本成立，把追问点补进文档 |
| 需要改 L0/L1 才能跑通 | 规格有洞，补文档后重测 |
| 跑不通 | 母体未成立，不许对外宣称「通用」 |

### 反自欺条款

**禁止用「我自己跑一遍」代替空仓再造。** 作者自己跑通证明的是「作者会用」，不是「母体可复制」。

## 六、母体版本纪规

- 每次空仓再造成功 → 记一个版本号，写进 `06-复盘/`
- L0 十条**不编号版本**（永久冻结）；版本只记 L1 骨架与契约格式
- 契约字段只准**加**，不准改语义、不准删 —— 删改会让历史信封无法解析
