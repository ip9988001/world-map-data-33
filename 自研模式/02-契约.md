# 四份契约（照抄，不许自由发挥格式）

> 契约的作用：让大脑**不必读日志**就能核验，让任何第三方**只凭契约内容**就能定位与复算。
> 缺字段一律拒收。**拒收优于容错** —— 一条定位不了的消息进了队列，还得花大脑的时间去追问。

---

## 一、信封契约（工头 → 大脑 的唯一消息格式）

任何工头、任何仓库，要叫大脑，必须提交这个信封。投递走统一信箱（队列），**不许直连大脑**。

### 必填字段

| 字段 | 说明 | 为什么必填 |
|---|---|---|
| `repo_full_name` | `owner/repo` | 定位仓库 |
| `repo_url` | 完整克隆地址 | 让大脑能克隆核对 |
| `workflow_name` | 哪个 workflow 在监控 | 定位监控对象 |
| `run_id` / `run_url` | 本次运行 | 定位到具体一次运行 |
| `step_id` / `step_title` | 哪一步、这步负责什么 | 定位环节 |
| `step_contract` | 目标 / 输入 / 产出 / 验收判据 / 失败形态（五段） | 让大脑不必回仓库找判据 |
| `layer_id`（或任务单元 ID） | 卡在哪一个具体单元 | 单点重跑的前提 |
| `attempt` | 第几次尝试 | 判「两次即跳」 |
| `script_sha` | 执行时脚本的 hash | 分清新旧口径，防混账 |
| `evidence_urls` | 证据指针（文件/artifact/查询语句） | 复算入口 |
| `priority` | `P0` / `P1` / `P2` | 排队顺序 |
| `expected_done_at` | 预期完成时间（D4 实测外推） | 超期报警的唯一依据 |
| `sender_id` | 工头实例 ID | 退信与限流归属 |

### 分级语义（按后果分，不按情绪分）

| 级 | 含义 | 处理 |
|---|---|---|
| **P0** | 阻断：失败 / 契约不符 / 超期未到 / 静默不产出 | 插到队头，立即叫醒；**不抢占手上这一条** |
| **P1** | 需判断：blocked 待决策 / 数据偏差 / 需改脚本 | 正常排队 |
| **P2** | 进展 / 完成 / 心跳 | **必须折叠**，一段时间合并成一条摘要 |

> P2 不折叠会立刻出事：大规模任务会产生上千条进展，逐条推等于把信箱淹掉。

### 其它强制行为

- **幂等**：dedupe key = `run_id + step_id + event`，重投不重处理。
- **退信**：信箱处理不了 → 回写 reject reason 给 `sender_id`，工头修信封重投。不许消息黑洞。
- **限流**：每仓每小时上限。目的不是防谁，是**一个坏仓库别把别人的 P0 挤死**。
- **心跳超期由信箱侧判定**：工头只管投，判「该来的没来」是信箱的职责。这样即使 runner 天生不叫人，大脑也能被叫。

## 二、账本契约（append-only 事件流）

**禁止覆盖式快照。** 只允许追加事件。

```
(layer_id, ts, step_id, status, unit_rows, declared_rows, script_sha, evidence, run_id, attempt)
```

- `status ∈ {ok, partial, failed, skipped, blocked}`
- 任何「当前状态」都是**派生视图**，不落盘为唯一真相
- 追加写 + 不改历史；纠错也靠追加一条 `correction` 事件

**为什么**：增量重跑（「改哪层只跑哪层」）与数据溯源，全都建立在这一条上。覆盖写一出现，两者同时失效。

## 三、报告契约（manifest 四件套）

每个环节的产物目录必须带一份 `manifest.json`，字段锁死：

```json
{
  "expected": 0,
  "actual": 0,
  "status": "ok|partial|failed",
  "code_sha": "…"
}
```

可选附加：`units[]`（每单元的 rows）、`excluded[]`（排除项及理由）。

大脑核验 = diff `expected` 与 `actual`，不再读日志。
**任一项缺失 → 该环节视为未完成**，不许用「日志看着对」替代。

---

## 四、环节契约模板（STEP-0X.md）

```markdown
# STEP-0X <环节名>

## 目标
<一句话，可判真假>

## 输入
<来源 / 格式 / 已知缺口>

## 产出
<路径 / 命名 / 量级>

## 验收判据
<机器可算的表达式，例：manifest.actual == declared 且 差额已解释>

## 常见失败形态对照表
| 症状 | 分类 | 动作 |
|---|---|---|
| 0 行但无报错 | logic | 改代码，禁止重试 |
| HTTP 500 / 超时 | transient | 直接重跑，上限 2 次 |
| Invalid URL / 服务下线 | upstream | 找替代，找不到记档跳过 |
```

> 判据写成形容词（「基本完整」「大致对齐」）即为不合格，回 D1 重写。
