# P8 拍板建议：22 层路段门牌区间（from/to addr + 街名）

## 事实

| 项 | 值 |
|---|---|
| 层数 | 22（`analysis/combo-step1-20261125/patterns.csv` 的 `pattern_id=P8`） |
| 行数 | 184,987（`rows_n` 合计） |
| 结构 | 中心线层：`FROMADDR`/`TOADDR`、`FROMADDRESSLEFTTHEO`/`TOADDRESSLEFTTHEO`、`RangeNumber`、`LFROMHN/LTOHN` 这类**起点/终点门牌**，配 `FULLNAME`/街名列 |
| 真实样本 | 995 行（coord-samples），全部有值（例：`700 → 1534`、`30399 → 30339`） |
| 几何 | 线（中心线）；坐标本身就是「路段」，没有单点 |

## 为什么不能直接套 E7 的键

E7 的键是 `state|门牌|街名|zip`（单点门牌）。区间层只有「起止门牌 + 街名」，要参与 E7 必须**反向匹配**：
拿另一源的某个门牌 N，判断 `from ≤ N ≤ to` 且街名相同 —— 这是新的匹配器（含左右侧 L/R 单双号规则、奇偶规则），
不是别名或切分能解决的。

## 成本 / 收益

| 方案 | 成本 | 收益 |
|---|---|---|
| A. 单独建模区间匹配 | 要新增匹配器（左右侧 + 奇偶 + 端点包含）+ 单测 + 与 E7 投票口径协调；估 1 轮完整任务（≈3–4h 有效工时），且会**放大误匹配**（区间天然覆盖多个门牌，一票能同时命中多源） | 22 层 / 184,987 行；占组合拳① 缺口 1,340 层的 **1.64%** |
| B. 从 E7 可验分母剔除 | 一次口径改动 + 归因说明 | 立刻让缺口口径干净（这 22 层永不出键是数据性质，不是缺陷） |
| C. 只做「端点精确匹配」 | 便宜（from/to 当作两个静态门牌，各自建键） | 真实性差：中心线端点门牌 ≠ 该点门牌，会把「街段起点」当成「地址点」，**不建议** |

## 建议（一句可执行）

**选 B：把 P8 的 22 层从 E7 可验分母剔除**，在同一份归因说明里标注「路段区间层，需专用区间匹配器，暂不计入」；
若未来要补，走独立任务建「区间匹配器」（方案 A），不与本轮切分路线混做。

## 需要 Muse 点头的那一条
