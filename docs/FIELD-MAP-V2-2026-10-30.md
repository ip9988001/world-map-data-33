## 三、门牌号与街名：原生取列 vs 从整串地址切

- `house_number` 原生列：**860 层**；从整串地址（ADDRESS/FULLADDR/SITUS_ADDR…）用 `^(\d+[A-Za-z]?)` 切首段：**1129 层**（标 `quality=extracted`，下游可分级信任）
- 有 **82 层**的门牌列里 `0` 占比 >5%（`zero_share` 已写入逐层），`0` 是「无门牌号」占位，SCHEMA 要求保留原写法，但**入 gold 时应按无门牌号处理**
- 切分时 `street_name` 强制取**同一列**（同一行才对得上），不会出现「号来自 A 列、名来自 B 列」的错配

## 四、state_abbr：为什么这次能到 91.6%

- 源层有州列且示例合法：**722 层**
- 源层没有州列，取**层元数据**（`collect/*_layers.csv` 的 `state`）：**1520 层**
- 两者都没有：**122 层**（层标题不含州名，如 `Poland_Addresses_2_view`）

理由：州是**分片作用域属性**，SCHEMA 2.0 自己也写了「县片内实测 100% 等于本州」，所以用层元数据补 state 不算伪造；v1 把「源层没有 state 列」判成 unusable 是口径错误。

## 五、4 个三仓溯源字段（建议名与取值）

二仓 19 个溯源列（`src_nad_uuid` / `src_oa_hash` / `src_tiger_tlid` / `src_overture_id` …）全部面向 NAD/TIGER/OA/Overture。三仓是 ArcGIS 点层与宗地层，这些 id 一个都没有 —— 不加这 4 列，地址无法回溯到原始层与原始宗地。

| 建议字段名 | 类型 | 可空 | 取值规则 | 实测覆盖 |
|---|---|---|---|---|
| `src_kind` | enum | 否 | 层几何/来源判定：点层=address_point，宗地层=parcel_situs；street_line 三仓暂无，保留待用 | {"parcel_situs": 1238, "address_point": 1126} |
| `src_layer_id` | string | 否 | 三仓层标识（ArcGIS service 层名规范化），即 Release tag `collect-step<NN>-<layer_id>` 里的那段 | 2364/2364 |
| `src_layer_url` | string | 是 | 层元数据里的 ArcGIS REST 端点（来自 collect/*_layers.csv，仅记录不访问） | 2349/2364 |
| `src_parcel_id` | string | 是 | 仅 parcel_situs 层：源层 parcel id 列（ParcelID/APN/PIN/PARCEL_NUMBER…）；点层恒为 null | 686/1238 宗地层 |

`src_kind` 取值严格限定在既有枚举 `address_point|parcel_situs|street_line`：三仓本轮只有前两种，`street_line` 保留待用（不新造枚举值）。

## 八bis、state / county 回填（B 项）

| 口径 | 层数 | 占比 | 说明 |
|---|---|---|---|
| v1 口径（house_number + street_name + **state 列**） | 587 | 24.83% | 只认源列，所以大批「州只在层元数据里」的层被判不可用 |
| v2（state 按层清单回填后） | 1820 | 76.99% | 州是分片作用域属性，用层元数据补不算伪造 |
| v3（+ 县可判：层名单县 222 层，或逐行 TIGER 多边形判得出） | 984 | 41.62% | 掉下来的原因是宗地层缺坐标（992 层跨多县且无经纬度），需几何质心 |

county 的两条路径：

- **层名单县**：222 层（源列 99 + 从层 id/url 反查 TIGER 123 层）
- **层跨多县**：2142 层 → county_fips 不能写死，必须逐行判定；其中 992 层连坐标都没有，属 `geo_missing`

**禁用 bbox 的实证**（`collect/county_tiger.py --selftest GA`，结果落 `analysis/tiger_county/selftest.json`）：

| 检验 | 结果 |
|---|---|
| GA 县界顶点 31,386 个做对照 | 14,514 个（46.2%）会同时落进**邻县**的 bbox |
| GA 真实地址点抽样 2,000 个 | bbox 歧义（≥2 县）**2,000 条 = 100%**；多边形判定失败 **0 条** |

所以 county 一律走射线法 point-in-polygon，bbox 只用来快速跳过候选，**绝不作为判定依据**。

## 九、别名表里的坑（实测踩到，已写进代码注释）

| 字段/列 | 坑 | 处理 |
|---|---|---|
| `CITY` | 语义族里最不确定：有的层是 USPS 城市，有的是市政城市 | 进 `postal_city` 但列为**待抽样核验项** |
| `OWNER_CITY` | 业主邮寄城市，实测值含 `MIAMI, FL 33142-2202` | **不进** `postal_city`（v1 混用过） |
| `MUNICIPALITY` | 实测含 `Unincorporated Area` | 只进 `municipal_city` |
| `UNITID` | E911 里常混状态码（`PKG`/`RPDSEC`） | 收，但 `quality=native_weak` |
| `POSTAL` | 有的层存 ZIP（`29406`），有的存城市名（`GASTONIA`） | ZIP 与 city 两张表都列，靠 5 位/字母校验器按层裁决 |
| `YEAR_BUILT` / `Ymin` / `LongLabel` / `Placement` | 前缀相似，v1 的正则前缀匹配会误命中 | 一律**全名匹配**，且经纬度要过 US 范围校验 |
| 门牌列 `0` | 占位值，实测 82 层 `0` 占比 >5% | 保留原值 + 写 `zero_share`，入 gold 当无门牌号 |
